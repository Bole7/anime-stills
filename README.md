# 近期日漫截图分享 · Anime Stills

一个近期日本动画截图的分享站。打开就是一圈会缓慢自转的**环幕**，把喜欢的画面停下来看。

> Web 全栈开发课程作业 · 王博乐

---

## 一、设计定调

| 项 | 决策 |
|---|---|
| **目的** | 把散在相册里的动画截图，变成一个能"翻着看"的地方 |
| **调性** | 亮色「纸感画廊」—— 暖白纸底、墨黑铅字、唯一朱红强调色 |
| **展示字** | Cormorant Garamond（拉丁衬线）+ 中文宋体栈 |
| **正文字** | 系统黑体栈（PingFang SC / 微软雅黑） |
| **元数据字** | JetBrains Mono（日期、标签、计数统统一把等宽尺） |
| **记忆点** | 巨大的 3D 环幕：8 张画面围成圆柱，自己慢慢转，可以拖可以翻 |

配色只用三档：`--paper #F4F2EC` 纸底 / `--ink #16150F` 墨字 / `--accent #C4432B` 朱红。
朱红全站只出现在"停下来"三个字这类关键位置，其余一律黑白。

**画面之外不放字。** 首页从导航直接进入环幕，没有站名、没有标识、没有编号，
没有控制条、没有说明文字；目录区是筛选条直接接图片网格，每张图下面也没有题名或标签。
想读信息就点开看大图，不点开就只有画面本身。

页面唯一可见的文字是顶部导航、筛选条、关于区与页脚 —— 其余全是图。
上传入口只用一个加号图标；旁边那个「＋ 分类」带了两个字，是因为它是个动作而不是筛选状态，
不写清楚没人猜得到它干什么。

标题（`h1`）保留在 DOM 里但视觉隐藏（`.sr-only`），语义与屏幕阅读器不受影响。

## 三、怎么运行

**方式一：直接打开。** 双击 `index.html` 即可，不需要任何构建工具、不需要联网
（字体走 Google Fonts，加载不到会优雅回退到系统衬线体）。

**方式二：本地服务器。**

```bash
python -m http.server 8080
# 然后访问 http://127.0.0.1:8080
```

## 四、功能清单

**环幕轮播（首屏）**

- CSS 3D 圆柱：面板 `rotateY(i·step) translateZ(R)` 围成环，`perspective` 做景深
- **上环幕的画面由你选**：默认 8 张，任意一张都能放上去或撤下来（最少留 3 张），
  张数一变，圆柱的夹角、半径、透视尺寸当场重算，环幕始终是闭合的
- 半径不是写死的：先定"屏幕上想看到多大"，再由透视公式反推面板实宽与圆柱半径
- 自动旋转（6°/秒）、拖拽旋转（带惯性衰减）、松手吸附到最近一张
- 键盘 `←` `→` 翻一张，`空格` 暂停/继续自动旋转
- 触控板横向滑动可以转，纵向滚动仍然留给页面（不劫持滚动）
- 非当前画面盖一层纸色遮罩"未点亮"，当前那张才亮起来 —— 亮色主题下的聚焦手法

**目录网格：按番剧分堆**

- 分类就是番剧名，**名字由你自己写**，不预设
- 筛选条末尾的 `＋ 分类` 就地变出一个输入框，打完回车就建好，不弹系统对话框
- 自建分类双击（触屏长按）就地改名；悬停时 chip 右端浮出 `×` 可整条删掉，
  删掉后底下的画面退回「未分类」，**图片一张不丢**
- **拖拽转移**：把任意一张拖到某个分类上，松手即归入，该分类高亮、计数同步；
  转移后若与当前筛选不符，它会立刻从视图里退出去
- 每条画面右上角还有一个"移动到"浮层入口（桌面悬停浮出、触屏常驻），里面列出全部分类，
  可以直接选，也能顺手新建一个并移进去
- 内置素材一开始都在「未分类」里等你分堆
- 图片下面不落任何文字；有题名的那几张，悬停时才浮出一条题名

**灯箱**

- 点击任意画面放大，图片下方一条信息栏显示序号、所属分类、日期
- `←` `→` 在**当前筛选结果内**翻页，`Esc` 关闭，焦点自动回到触发元素
- `Tab` 键在灯箱内循环，不会跑到底层页面

**上传自己的图**

- 两个入口：筛选条末尾的虚线 `＋`，或把图片直接拖进页面（拖拽时有整屏投放提示）
- **上传时在哪个分类下，图就归到哪个分类**，不用传完再手动拖一遍
- 全程在浏览器里处理，图片不上传任何服务器：`canvas` 缩放 → WebP 编码 → 落到 IndexedDB
- 色调标签仍会当场算出来（跟内置 53 张同一套算法与阈值），存进灯箱信息里备用
- 自传的图排在网格最前，刷新后仍在，移除后也不再回来
- 横图竖图都能传：长边压到 1440px，灯箱里按原比例完整显示，不会溢出屏幕

**触屏上的降级路径**

- 触屏没有 hover，卡片操作条改为常驻；HTML5 拖拽在这类设备上不启用（长按会跟系统手势打架）
- 卡片上只留一个「移动到」按钮，**环幕开关与移除都收进浮层里**，
  免得三个按钮常驻把画面盖住

**其他**

- 首屏一次编排好的入场序列（3 组，60/180/300ms 错峰）
- 滚动触发的 `IntersectionObserver` 入场，卡片按 4 档错峰
- 导航栏滚过 12px 后转为毛玻璃条
- 全部动效在 `prefers-reduced-motion: reduce` 下一律关闭

## 五、关于素材

素材是个人追番时的收藏截图，共 53 张，均为 1919×1079 原始比例。按番剧分堆的归属由使用者自定，
所以内置的这批一开始都待在「未分类」里，拖一下就归位了。

原图右下角带平台水印，处理时用**局部取样修补**（取同高度左侧背景覆盖并羽化边缘）去掉水印，
而不是直接裁掉底部 —— 保住了完整的 16:9 构图。画面里的字幕保留了下来，那是截图的一部分。

WebP 三档尺寸由 Pillow 批量生成，全部素材合计约 3.3 MB。

## 七、技术说明

- 纯原生 HTML / CSS / JavaScript，**零依赖、零构建**
- 脚本用 IIFE 封装，不用 ES Module —— 因为 `file://` 协议下模块加载会被跨域策略拦截，
  这样可以保证作业发给老师后双击就能看
- 数据以 `.js` 文件而非 `.json` 注入，原因同上（`fetch` 本地文件同样被拦）
- **分类的持久化分三份存**：分类表、每张图的归属覆盖、环幕名单，都走 `localStorage`。
  自传图片的归属与环幕状态**再往 IndexedDB 的记录里补写一份**，这样即使浏览器数据被清过一半，
  图片的归属也不会莫名回退。改归属用的是"就地补写字段"而不是整条覆盖，避免把 Blob 读出来再写回去
- **删分类时只动该分类下的图**。这一条踩过坑：一开始图省事把所有自传图片的记录都重置了一遍，
  结果删掉 A 分类会把还在 B 分类里的图也打回未分类。修法是先把成员列表取出来再清 `assignMap`，
  因为 `assignMap` 一清就查不出谁原来在哪了
- **色调归档**：把图片画到 160×90 的 canvas 上逐像素转 HSV，统计明度均值、饱和度均值，
  以及色相落在暖区（<90° 或 >300°）、冷区（150°–300°）的像素占比，再按固定阈值
  归到夜色 / 明亮 / 暖调 / 冷调 / 低饱和。内置素材是构建时用 Python 算的，
  上传的图是浏览器里用同一套公式现场算的，两边标准一致。现在这个标签不再用作筛选维度，
  但仍存在数据里、显示在灯箱信息栏上
- **上传图片的留存**用 IndexedDB 存 Blob，不用 localStorage 的 base64（那个几兆就满了）。
  个别浏览器在 `file://` 下会禁用 IndexedDB，所以做了降级：存不进去就只在本次会话保留，
  并在提示里注明「本次有效」，功能不中断
- 上传的图先经 `canvas` 缩到长边 1440px 再编码成 WebP，一张约两三百 KB，
  拖动几十张也不会把页面拖垮（上限 60 张）
- 桌面与触屏走的是**同一套转移逻辑**（拖拽与浮层都落到 `moveFrame`），
  差别只在入口：触屏关掉 HTML5 拖拽、把动作收进浮层，不另写一套
