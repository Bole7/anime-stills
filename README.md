# 近期日漫截图分享 · Anime Stills

一个近期日本动画截图的分享站。打开就是一圈会缓慢自转的**环幕**，把喜欢的画面停下来看。

> Web 全栈开发课程作业 · 王博乐

---

## 一、设计定调

| 项 | 决策 |
|---|---|
| **目的** | 把散在相册里的动画截图，变成一个能"翻着看"的地方 |
| **调性** | 亮色「纸感画廊」—— 暖白纸底、墨黑铅字、唯一朱红强调色 |
| **展示字** | Cormorant Garamond（拉丁衬线）+ 中文宋体栈 |
| **正文字** | 系统黑体栈（PingFang SC / 微软雅黑） |
| **元数据字** | JetBrains Mono（日期、标签、计数统统一把等宽尺） |
| **记忆点** | 巨大的 3D 环幕：8 张画面围成圆柱，自己慢慢转，可以拖可以翻 |

配色只用三档：`--paper #F4F2EC` 纸底 / `--ink #16150F` 墨字 / `--accent #C4432B` 朱红。
朱红全站只出现在"停下来"三个字、选中的画面描边、灯箱序号这类关键位置，其余一律黑白。

**画面之外不放字。** 首页从导航直接进入环幕，没有站名、没有标识、没有编号，
没有控制条、没有说明文字；目录区是筛选条直接接图片网格，每张图下面也没有题名或标签。
想读信息就点开看大图，不点开就只有画面本身。

页面唯一可见的文字是顶部导航、环幕下方那颗「管理环幕」、筛选条、关于区与页脚 —— 其余全是图。
筛选条里那几个带字的（`＋ 分类`、`选择`）都是**动作而不是筛选状态**，
不写清楚没人猜得到一个加号和一个方框是干什么的；单纯的筛选状态一律只有一个名字加一个计数。

标题（`h1`）保留在 DOM 里但视觉隐藏（`.sr-only`），语义与屏幕阅读器不受影响。


## 三、怎么运行

**方式一：直接打开。** 双击 `index.html` 即可，不需要任何构建工具、不需要联网
（字体走 Google Fonts，加载不到会优雅回退到系统衬线体）。

**方式二：本地服务器。**

```bash
python -m http.server 8080
# 然后访问 http://127.0.0.1:8080
```

## 四、功能清单

**环幕轮播（首屏）**

- CSS 3D 圆柱：面板 `rotateY(i·step) translateZ(R)` 围成环，`perspective` 做景深
- **上环幕的画面由你选**：默认 8 张，任意一张都能放上去或撤下来（最少留 3 张，最多 24 张），
  张数一变，圆柱的夹角、半径、透视尺寸当场重算，环幕始终是闭合的
- **管理环幕**：环幕下方那颗按钮打开面板，两排缩略图分列「在环幕上」与「还没上环幕」，
  点一下就加上、再点一下就移下；灯箱外的两排就是全部候选，不用回目录里翻。
  面板里还有「上传图片并上环幕」（传完直接进环幕，不用再挑一次）、
  「全部放上去」、「恢复默认」三件事，名单写进 `localStorage`，刷新后原样还在
- 三处入口都能改环幕：卡片右上角的环幕图标（桌面悬停浮出 / 触屏在浮层里）、管理面板、批量上传
- 半径不是写死的：先定"屏幕上想看到多大"，再由透视公式反推面板实宽与圆柱半径
- 自动旋转（6°/秒）、拖拽旋转（带惯性衰减）、松手吸附到最近一张
- 键盘 `←` `→` 翻一张，`空格` 暂停/继续自动旋转
- 触控板横向滑动可以转，纵向滚动仍然留给页面（不劫持滚动）
- 非当前画面盖一层纸色遮罩"未点亮"，当前那张才亮起来 —— 亮色主题下的聚焦手法

**目录网格：按番剧分堆**

- 分类就是番剧名，**名字由你自己写**，不预设
- 筛选条末尾的 `＋ 分类` 就地变出一个输入框，打完回车就建好，不弹系统对话框
- 自建分类双击（触屏长按）就地改名；悬停时 chip 右端浮出 `×` 可整条删掉，
  删掉后底下的画面退回「未分类」，**图片一张不丢**
- **拖拽转移**：把任意一张拖到某个分类上，松手即归入，该分类高亮、计数同步；
  转移后若与当前筛选不符，它会立刻从视图里退出去
- 每条画面右上角还有一个"移动到"浮层入口（桌面悬停浮出、触屏常驻），里面列出全部分类，
  可以直接选，也能顺手新建一个并移进去
- 内置素材一开始都在「未分类」里等你分堆
- 图片下面不落任何文字；有题名的那几张，悬停时才浮出一条题名

**批量选择**

- 筛选条末尾的「选择」切进选择模式，底部浮出一条操作条：已选计数 / 全选 / 反选 / 清空 /
  移动到 / 移除 / 完成
- 三种选法：**点一下挑一张**；**按住 Shift 点**把上一次到这一次之间整段连选；
  **在空白处拖一个框**，压到多少选多少（框选只在有鼠标的设备上开，触屏上按住拖动是滚动页面）
- **拖一整个选区**：拖选区里的任意一张到分类 chip 上，整批一起搬走
- **批量移除**：自传图片真删（含 IndexedDB 里的记录），内置截图记一笔**隐藏**——
  内置素材是仓库里的文件，删不掉，隐起来但随时能整批放回来。
  筛选条上会出现「恢复隐藏 05」，点一下全部还原
- 自传图片的删除不可逆，所以那个按钮要多按一下才动手（按钮当场变成"确认删掉 N 张？"），
  内置截图只是隐藏，不必确认
- 键盘：`Ctrl/Cmd + A` 全选当前筛选下的画面，`Esc` 退出选择模式

**灯箱**

- 点击任意画面放大，图片下方一条信息栏显示序号、所属分类、日期
- `←` `→` 在**当前筛选结果内**翻页，`Esc` 关闭，焦点自动回到触发元素
- `Tab` 键在灯箱内循环，不会跑到底层页面

**上传自己的图**

- 两个入口：筛选条末尾的虚线 `＋`，或把图片直接拖进页面（拖拽时有整屏投放提示）
- **上传时在哪个分类下，图就归到哪个分类**，不用传完再手动拖一遍
- 全程在浏览器里处理，图片不上传任何服务器：`canvas` 缩放 → WebP 编码 → 落到 IndexedDB
- 色调标签仍会当场算出来（跟内置 53 张同一套算法与阈值），存进灯箱信息里备用
- 自传的图排在网格最前，刷新后仍在，移除后也不再回来
- 横图竖图都能传：长边压到 1440px，灯箱里按原比例完整显示，不会溢出屏幕

**触屏上的降级路径**

- 触屏没有 hover，卡片操作条改为常驻；HTML5 拖拽在这类设备上不启用（长按会跟系统手势打架）
- 卡片上只留一个「移动到」按钮，**环幕开关与移除都收进浮层里**，
  免得三个按钮常驻把画面盖住
- 环幕管理面板在窄屏上从底部推出，占满宽度，缩略图两排横向滚动，按钮排成一行加一个通栏的「完成」
- 批量选择在触屏上保留点选（选择圈放大到 32px），框选与 Shift 连选自动关闭，
  靠「全选 / 反选」补齐"一次选很多"这条路径

**其他**

- 首屏一次编排好的入场序列（3 组，60/180/300ms 错峰）
- 滚动触发的 `IntersectionObserver` 入场，卡片按 4 档错峰
- 导航栏滚过 12px 后转为毛玻璃条
- 全部动效在 `prefers-reduced-motion: reduce` 下一律关闭

## 五、关于素材

素材是个人追番时的收藏截图，共 53 张，均为 1919×1079 原始比例。按番剧分堆的归属由使用者自定，
所以内置的这批一开始都待在「未分类」里，拖一下就归位了。

原图右下角带平台水印，处理时用**局部取样修补**（取同高度左侧背景覆盖并羽化边缘）去掉水印，
而不是直接裁掉底部 —— 保住了完整的 16:9 构图。画面里的字幕保留了下来，那是截图的一部分。

WebP 三档尺寸由 Pillow 批量生成，全部素材合计约 3.3 MB。

> 仅用于课程作业的学习与展示，不作任何商业用途。

## 七、技术说明

- 纯原生 HTML / CSS / JavaScript，**零依赖、零构建**
- 脚本用 IIFE 封装，不用 ES Module —— 因为 `file://` 协议下模块加载会被跨域策略拦截，
  这样可以保证作业发给老师后双击就能看
- 数据以 `.js` 文件而非 `.json` 注入，原因同上（`fetch` 本地文件同样被拦）
- **分类的持久化分四份存**：分类表、每张图的归属覆盖、环幕名单、被隐藏的名单，
  都走 `localStorage`。自传图片的归属与环幕状态**再往 IndexedDB 的记录里补写一份**，
  这样即使浏览器数据被清过一半，图片的归属也不会莫名回退。
  改归属用的是"就地补写字段"而不是整条覆盖，避免把 Blob 读出来再写回去
- **「删除」内置截图其实是隐藏**。内置素材是仓库里的静态文件，前端删不掉；
  与其弹一句"删不了"，不如记一笔隐藏 —— 行为上跟删掉一样（从目录、计数、环幕里一并退出），
  但给了一个「恢复隐藏」的回退口子，不至于让人手滑一次就永久损失一批素材
- **素材分档寻址，且不假设文件一定存在**。内置截图有三档尺寸，但只有 8 张备了
  1600px 的大图；早先环幕对任何一张都去要 `assets/hero/xx.webp`，于是"把一张没大图的截图
  放上环幕"就成了一张破图。现在 `frames-data.js` 里多出一份 `heroAssets` 名单，
  环幕先查名单，不在名单里的退回 1200px 的 `view` 档；图片上还挂了 `error` 兜底
  （hero → view → grid 逐级降档），全都不行才判为素材缺失
- **取不出来的画面不留破图**。判为缺失的那张会从环幕与候选中退出，卡片位置立一句"素材缺失"，
  环幕面板里多出一段「素材缺失」列出它们，点一下就清掉（自传真删、内置记隐藏）——
  比留一堆浏览器默认的破图图标体面，也给了明确的去路
- **面板里那排不换行的缩略图踩过一个 layout 坑**：`display: grid` 的容器里，
  网格项默认按 `max-content` 撑开，一排 45 张缩略图会把卡片撑到四千多像素宽，居中之后
  屏幕上只剩中间一段空白。给列加上 `minmax(0, 1fr)` 才收得住，横滚交给 `overflow-x`
- **批量与单张共用一条转移路径**：`moveFrames(list, id)` 收一个数组，单张就是长度 1 的数组。
  拖拽、归类浮层、批量操作条都落到这一个函数，所以"拖一批"和"拖一张"不会出现两套行为
- **选中态不跟着筛选走**。切到别的分类时已选的那些仍然算数（计数照旧），
  这样才能"在 A 分类里选几张、切到 B 再选几张、最后一起搬" —— 这是把选区存成
  一张 id 表而不是一组 DOM 节点的原因
- **删分类时只动该分类下的图**。这一条踩过坑：一开始图省事把所有自传图片的记录都重置了一遍，
  结果删掉 A 分类会把还在 B 分类里的图也打回未分类。修法是先把成员列表取出来再清 `assignMap`，
  因为 `assignMap` 一清就查不出谁原来在哪了
- **色调归档**：把图片画到 160×90 的 canvas 上逐像素转 HSV，统计明度均值、饱和度均值，
  以及色相落在暖区（<90° 或 >300°）、冷区（150°–300°）的像素占比，再按固定阈值
  归到夜色 / 明亮 / 暖调 / 冷调 / 低饱和。内置素材是构建时用 Python 算的，
  上传的图是浏览器里用同一套公式现场算的，两边标准一致。现在这个标签不再用作筛选维度，
  但仍存在数据里、显示在灯箱信息栏上
- **上传图片的留存**用 IndexedDB 存 Blob，不用 localStorage 的 base64（那个几兆就满了）。
  个别浏览器在 `file://` 下会禁用 IndexedDB，所以做了降级：存不进去就只在本次会话保留，
  并在提示里注明「本次有效」，功能不中断
- 上传的图先经 `canvas` 缩到长边 1440px 再编码成 WebP，一张约两三百 KB，
  拖动几十张也不会把页面拖垮（上限 60 张）
- 桌面与触屏走的是**同一套转移逻辑**（拖拽与浮层都落到 `moveFrames`），
  差别只在入口：触屏关掉 HTML5 拖拽、把动作收进浮层，不另写一套
- 框选用的是文档级 `pointermove` 加一个 `position: fixed` 的矩形覆盖层，
  每帧拿卡片 `getBoundingClientRect()` 做相交判断 —— 几十张的量级下开销可以忽略，
  没必要上"取一次坐标缓存起来"那种优化，反而容易在滚动后算错
- 底部操作条踩过一个坑：`position: fixed` 的元素宽度本来按"收缩到合适"算，
  而它同时用了 `left: 50%` 居中，可用宽度就只剩半个视口 —— 窄屏上整条会被挤成一列竖排。
  显式写 `width: max-content` 再用 `max-width` 兜住即可
